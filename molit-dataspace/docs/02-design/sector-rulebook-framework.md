## 1. 목적과 판정

이 문서는 교통모빌리티 분야 데이터 스페이스 규약의 네 요소를 회원, payload, 유즈케이스, 요금·정산으로 고정한다.
payload 표준은 §5의 범주 골격만 승인했고 필드 수준은 미결정이다 — 근거: `E-24`, 기준일: 2026-08-06.
운영 주체와 분야 DSGA는 KAIA 위임을 전제로 한 잠정 배정이며 공식 위임 문서는 미확인이다 — 상태: `Unverified`, 근거: `E-26`, `OPEN-TOP-06`.
분야 DSGA가 승인할 절차는 §5의 Gate에서 정의한다.

- 판정: 교통모빌리티를 첫 분야 규약 골격으로 채택
- 공통 기반: 참가자 신뢰, Connector·프로토콜 profile, 연합 Catalog, 공간 참조, 공통 정책 어휘
- 분야 책임: 회원 세부규칙, payload 표준, 유즈케이스 backlog, 요금·정산 규칙
- 제외: 기관 지명, 정산 payload 필드 발명, 수치 요금 확정
- 설계 경계: 데이터 스페이스는 신원·카탈로그·계약·정책·감사를 담당하고 payload를 보관하거나 중계하지 않음
  - 실제 byte는 원천 플랫폼에서 Consumer로 직접 이동

[국가 프레임 아래 2계층 구성](../01-research/dataspace-topology-single-vs-sectoral.md#51-국가-프레임-아래의-2계층-구성)의 네 구성요소를 재정의하지 않고 이 규약의 참조 경계로 사용한다. 규칙 제정과 운영의 분리는 [ADR-0007 §1](../adr/0007-governance-function-separation.md#1-목적과-결정-요약)을 따른다.

원천 유지와 직접 전달 경계는 [ADR-0002](../adr/0002-data-stays-at-source.md)와 [EDC·CaaS·DSaaS 아키텍처 §6](../02-architecture/edc-caas-dsaas-architecture.md#6-offering-게시와-전송)을 따른다.

## 2. 규약 권한과 역할

IDSA Rulebook Release 2026-1에서 기술 역할은 Participant와 데이터 스페이스 거버넌스 기관(Data Space Governance Authority, DSGA)이다.

Provider와 Consumer는 계약별 기능으로 취급한다. 근거: [IDSA Rulebook 역할](https://kb.internationaldataspaces.org/external/rulebook/005_Roles/), 확인일 2026-07-30

- **(Decision, E-16)** 계약별로 **Provider 기능을 수행하는 주체의 기본값은 원천기관**이다. 허브가 특정 데이터셋에서 Provider 기능을 수행하려면 **포괄 위임이 문서로 확인**돼야 한다
- **(해석 경계)** E-16은 계약별 기능의 기본 수행 주체를 정한다. 원천기관을 고정된 기관 지위로 만들거나, 문서로 확인된 포괄 위임 범위에서 허브의 Provider 기능 수행을 배제하지 않는다.

| 역할 | 규약상 책임 | 비책임 | 상태 |
| --- | --- | --- | --- |
| 공통 기반 DSGA | 공통 참가·신뢰·프로토콜·공간 참조 제약 승인 | 분야 payload와 요금 수치 승인 | 후보 — ADR-0007 Proposed |
| 교통모빌리티 DSGA | 분야 회원 세부규칙, payload, 유즈케이스, 요금·정산 규칙 승인 | 공통 profile 개정과 서비스 운영 | KAIA 잠정 — 공식 위임 문서 확인 대기(`OPEN-TOP-06`) |
| Participant | 승인된 경로와 계약에 따라 Provider·Consumer 기능 수행 | 규칙 제정과 다른 Participant의 적법성 보증 | 주체별 가입 전 미확정 |
| 운영 주체 | 승인 규칙을 시스템 상태·계약·감사 기록으로 집행 | DSGA 규칙 제정 | KAIA 잠정 — 공식 위임 문서 확인 대기(`OPEN-TOP-06`) |

- **(Decision — E-26)** 분야 DSGA와 운영 주체는 KAIA 위임을 전제로 잠정 배정한다. 근거는 구두 전언이고 공식 위임·지정 문서는 미확인이다 — 상태: `Unverified`, 기준일: 2026-08-06
  - 결정 기록은 [거버넌스·운영 원칙 §6](governance-and-operating-principles.md#6-미결정-주체와-법문화)에 둔다. 이 배정을 확정 표기나 대외 인용으로 쓰지 않는다.

## 4. 회원 규칙 경계

회원 판정은 조직 이름만으로 완료하지 않는다. 분야 DSGA는 공통 기반의 참가 판정 ID를 입력으로 받아 교통모빌리티 유즈케이스의 역할과 경로를 추가로 승인한다.

1. 공통 기반은 기관 등록, 비즈니스 적격성, 경로 기반 등급과 credential 상태를 판정한다.
2. 분야 DSGA는 유즈케이스별 Provider·Consumer 기능, 제출 의무와 허용 자산 범위를 판정한다. 제출 이행 성립은 E-20의 세 조건을 별도로 충족해야 한다.
3. 운영 주체는 두 판정이 모두 유효한 경우에만 분야 Catalog·협상 경로를 연다.
4. 어느 판정이든 만료·철회되면 새 Agreement와 Transfer를 차단하고 재평가 상태를 기록한다.

## 5. Payload 표준 결정 Gate

### 5.1 범주 골격 승인

- **(Decision — E-24)** 정산 payload의 범주 골격을 **운행 실적·수입금 집계·비용 항목·대사 결과·공통 감사 ID**의 다섯 범주로 승인한다 — 근거: `E-24`, 기준일: 2026-08-06
  - 승인 범위는 범주 골격에 한정된다. 필드 수준 확정은 리서치와 실물 조사 결과로 본 Gate에서 수행한다.
- **(Decision — E-22)** 실물 조사의 우선 적용 도시는 청주시로 두되 잠정이며 파일럿 도시 선정의 확정이 아니다 — 근거: `E-22`, 기준일: 2026-08-06

도시별 원가 분류·필드 후보 초안은 [준공영제 정산 데이터 필드 실물 조사](../01-research/settlement-data-field-survey.md)를 참조한다.

### 5.2 기존 3범주와 E-24 5범주의 대응

기존 문서들은 초기 교환 범위를 **정산 명세·대사 결과·공통 감사 ID**의 3범주로 고정했다. E-24의 5범주와의 대응은 다음과 같다.

| 기존 3범주 | 대응하는 E-24 범주 | 대응 판정 | 비고 |
| --- | --- | --- | --- |
| 정산 명세 | 운행 실적·수입금 집계·비용 항목 | `Unverified` | 분해인지 범위 확대인지 미결정 — `OPEN-SRF-07` |
| 대사 결과 | 대사 결과 | `Decision` | E-24가 같은 이름의 범주를 유지 |
| 공통 감사 ID | 공통 감사 ID | `Decision` | E-24가 같은 이름의 범주를 유지 |

- **(Unverified)** 교환 범위가 3범주 대비 확대됐는지는 판정하지 않는다. 필드 수준 확정 전에는 분해·확대 어느 쪽으로도 기록하지 않는다 — `OPEN-SRF-07`
- **(표기 정본)** 이 규약과 참조 문서에서 **정산 명세**와 **대사 결과**는 띄어쓰기형을 정본 표기로 쓴다. 붙임형 표기는 정정 대상이다.

### 5.3 표준 채택 원칙과 Gate

D-11의 **원칙 후보**는 payload 표준을 기존 표준 조사 뒤 채택하고, 규약 골격 단계에서 필드나 code를 새로 만들지 않는다는 것이다. 분야 DSGA 승인 전에는 확정 규칙이나 구현 기준선으로 사용하지 않는다.

| Gate | 필요한 입력 | 통과 증거 | 실패 처리 |
| --- | --- | --- | --- |
| 실물 조사 | 교통카드 정산 명세, BIS/BMS 교환항목, 표준 노드링크 자료 | 출처·version·필드·관계 inventory | DEF-05 유지 |
| 기존 표준 대조 | 유즈케이스 필수 필드와 기존 표준 mapping | 일치·변환·손실 항목 표 | 손실 항목 미승인 시 제외 |
| 권리·민감도 판정 | 필드별 Provider 권한과 데이터 등급 | 자산 판정 ID와 허용 경로 | 미확정 필드 제외 |
| 분야 승인 | schema, identifier, version, migration, validation rule | 분야 DSGA 결정 기록 | 승인 전 구현 기준선 사용 금지 |

DEF-05의 선행 조건은 리서치와 실물 조사(우선 후보 청주, 잠정) 완료다. 이월 항목의 단일 조회 지점은 [DSSC 갭 등록 §3.2](../01-research/dssc-gap-register.md#32-이월-색인-정본)다.

## 6. 유즈케이스 등재

분야 backlog의 각 행은 다음 값을 가진다.

| 항목 | 기록 기준 |
| --- | --- |
| 식별자·상태 | 후보, 승인, 실증, 중단, 종료를 구분 |
| 참여 기능 | 계약별 Provider·Consumer와 운영 주체를 분리 |
| 가치·업무 경계 | 수혜자, 제출·조회·정산 동작과 제외 자산을 명시 |
| 데이터·경로 | 자산 판정 ID, payload version, 참가 등급을 연결 |
| 정책·계약 | 목적·수신자·기간, 법적 근거, Agreement 관계를 연결 |
| 결과 판정 | KPI, 중단조건, 검증 증거와 결정권자를 기록 |

첫 등재 후보와 KPI는 [초기 유즈케이스·KPI](../03-plan/initial-usecases-and-kpi.md)에서 관리한다. 후보 문서의 존재만으로 분야 DSGA 승인을 대신하지 않는다.

## 7. 요금·정산 자리

요금은 데이터 이용조건, 플랫폼 구독료와 유상 데이터 상품 결제를 분리해 기록한다. Marketplace와 결제 범위의 정본은 [상용 CaaS·DSaaS 기준선 §4.1](commercial-caas-dsaas-baseline.md#41-제품별-책임)과 상용 준비 register다.

| 구분 | 원장·계약 경계 | 규약이 확정할 항목 |
| --- | --- | --- |
| 공개 데이터 이용조건 | 기존 license와 DSP Offer | 출처표시·접근절차·quota |
| 관리형 서비스 구독 | CaaS·DSaaS 운영 계약 | 과금 단위, SLA, 변경·해지 |
| 유상 데이터 상품 | Marketplace 주문·결제 원장 | 가격, 세금, commission, refund, reconciliation |
| 정산 증적 | 데이터 계약·감사 ID·승인된 notary 범위 | 제출 주기, 대사 규칙, 이의·분쟁 절차 |

## 8. 제도화 순서와 법적 층위

### 8.1 제도화 순서

- **(Decision, E-13)** 제도화는 **고시·훈령을 먼저** 두고 **상위 법령은 뒤에 둔다**
- **(Verified)** 등록·제출·제공·연계 의무를 부과할 수 있는 조문은 13개 법률의 최소 31개 조문으로 확인됨.
- **(Inferred)** 일반 민간 참가자 전체에 상시 데이터 등록·교환을 강제하는 범용 선례는 없었다.
- **(Verified)** 조사 범위에서 제재까지 결합된 제도군은 다음 네 제도군으로 확인됨.
  - 부동산거래관리시스템(Real Estate Transaction Management System, RTMS)
  - 건설산업지식정보시스템(Knowledge Information System of Construction Industry, KISCON) 공사대장
  - 시설물통합정보관리체계(Facility Management System, FMS) 법정보고
  - 금융 마이데이터

근거는 [시스템 근거 법령과 의무 부과 조문 조사 §2.1](../01-research/legal-basis-precedents.md#21-핵심-판정), [§4.1](../01-research/legal-basis-precedents.md#41-13개-법률과-최소-31개-조문)과 [§5.1](../01-research/legal-basis-precedents.md#51-대표-제도군-4개)이다. 조사 기준과 외부 원문 확인일은 2026-08-02다.

- **(Verified)** 고시·훈령 선행 단계는 내부 조직, 기술구조, 응용 프로그램 인터페이스(Application Programming Interface, API), 메타데이터 표준, 위임된 절차·서식과 자발적 참가약정 범위다.
  - **(한계)** 지자체·공기업·민간에 새 일반 의무나 제재를 부과하는 사항은 후행 상위 법령의 검토 범위다.
  - **(근거)** [법적 근거 조사 §7.2](../01-research/legal-basis-precedents.md#72-고시훈령의-한계), [행정규제기본법](https://law.go.kr/LSW/lsInfoP.do?ancYnChk=0&lsId=001360), 확인일 2026-08-02

- **(Inferred)** 협약만으로는 법정 간주가 생기지 않는다. 협약은 당사자의 운영 책임을 정할 수 있지만 상위 자치법규의 의무와 특정 시스템 이용명령을 변경하지 못한다.
  - **(근거)** [의무화·간주 규정 선례 조사 §6](../01-research/mandate-and-deeming-precedents.md#6-법적-4층위와-협약-한계), 외부 원문 확인일 2026-08-02

## 9. 제출 이행과 정산 시스템

### 9.1 계약별 기능과 직접 수신

- **(Decision, E-19)** 기존 정산 시스템(회계처리·버스경영관리시스템)은 **Consumer로 온보딩**한다. 계약을 맺고 운수사 원천에서 당겨온다
- **(Decision)** 시스템은 존속하고 **바뀌는 것은 데이터가 들어오는 경로**뿐이다. 운수사 원천 플랫폼을 system of record로 유지하고 실제 byte는 원천에서 기존 정산 시스템으로 직접 이동한다.
- **(Decision)** 데이터 스페이스는 신원·카탈로그·계약·정책·감사를 담당한다. payload를 보관하거나 중계하지 않는다.
- **(구현 경계)** Provider transfer worker는 승인된 PULL 전송 사건을 받아 원천 플랫폼 token이나 signed URL을 발급한다. 이 worker는 EDC Data Plane이나 DSP endpoint가 아니다.

### 9.2 제출 이행의 세 조건

- **(Decision, E-20)** 제출 이행은 **계약 체결 + 수신 가능 상태 + 기술적 온보딩 완료**의 세 조건이 모두 충족된 때 성립한다

| 조건 | 이 규약의 적용 경계 | 미확인 경계 |
| --- | --- | --- |
| 계약 체결 | 해당 자산의 Provider·Consumer 기능 사이 계약이 성립한 상태 | 기계 판독 표현과 감사 기록 방법은 `DRV-03` |
| 수신 가능 상태 | Consumer가 계약 범위에서 Provider Data Plane을 경유해 운수사 원천의 자료를 당겨올 수 있는 상태(`E-21`) | 판정 시험과 증거는 `DRV-01` |
| 기술적 온보딩 완료 | 완료로 판정된 상태 | 판정 기준·증거와 참가자 수준 종단시험 절차는 `DRV-01`, 판정 주체는 `DRV-02` |

어느 한 조건도 다른 조건을 대신하지 않는다. 세 조건의 상태 표현과 감사 기록 방식을 확정하기 전에는 자동 제출 이행 판정 규칙을 만들 수 없다. 상태: Unverified — `DRV-01`~`DRV-03`

### 9.3 간주 문안 제안

- **(Decision, 제안)** 제품명을 고정하지 않고 세 조건을 결합한 다음 문안을 조례 또는 명시적으로 위임된 규칙의 입안안으로 제안한다.

> “운송사업자의 정산자료 및 증빙자료에 관하여 다음 각 호의 요건을 모두 갖춘 때에는 제○조에 따른 정산ㆍ보고 및 자료 제출을 이행한 것으로 본다.
>
> 1. 운송사업자와 시장 또는 시장이 지정한 정산기관 사이에 해당 자료에 관한 계약이 체결되었을 것
> 2. 시장이 지정한, 국토교통부 데이터 스페이스와 상호운용되는 정보처리체계가 운송사업자의 원천시스템에서 해당 자료를 수신할 수 있게 된 때에 해당할 것
> 3. 제○항에 따른 기술적 온보딩이 완료되었을 것”

- **(Unverified)** 위 문안은 법무 검토 전 확정이 아니다. 위임 근거, 조문 위치, 계약 당사자, 기술적 온보딩의 정의와 간주효과 범위는 문서 미확인 상태다. `OPEN-SRF-05`에서 확인한다.
- **(Verified)** 공공공사 전자대금지급 선례는 특정 제품명 대신 기능요건을 충족하는 시스템을 상위법과 시행규칙에 규정함.
  - **(근거)** [의무화·간주 규정 선례 조사 §7.3](../01-research/mandate-and-deeming-precedents.md#73-기능적-규정과-하위-항목), [건설산업기본법 제34조제9항](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1007962233), 확인일 2026-08-02
  - **(근거)** [건설산업기본법 시행규칙 제28조](https://www.law.go.kr/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=1013427319), 확인일 2026-08-02
- **(Inferred)** 시설물안전법 시행규칙 제3조제6항은 1회 제출로 시·군·구→시·도→국토교통부의 연쇄 보고·제출을 소거하는 국내 원형에 해당
  - **(근거)** [의무화·간주 규정 선례 조사 §4.3](../01-research/mandate-and-deeming-precedents.md#43-국내-원형-판정), [시설물안전법 시행규칙](https://www.law.go.kr/LSW/lsInfoP.do?ancYnChk=0&chrClsCd=010202&efYd=20260102&lsiSeq=282381&urlMode=lsInfoP), 확인일 2026-08-02

### 9.4 경과 규정

- **(Decision, E-15)** 기존 **제출 창구** 대체 목표를 **2028년**으로 옮기고 2027년은 병행 시범·준비기간으로 재정의한다 — 근거: `E-15`, 기준일 2026-08-03
- **(Inferred)** 기술적 온보딩이 완료되지 않은 참가자는 E-20에 따른 제출 이행이 성립하지 않으므로 기존 경로 병행을 전제로 한 경과 규정 필요 — `DRV-04`
  - **(한계)** 기존 경로의 종료 조건과 전환 일정은 온보딩 완료율에 종속된다. 기간이나 완료율 기준은 확정하지 않는다. `DRV-04`에서 확인한다.

## 11. 검증과 변경 기록

규약 개정은 요소별 승인자, 입력 version, 변경 사유, 적용일과 rollback 조건을 기록한다. 자동 검증은 schema·참조·상태 전이를 확인하고, 사람 검수는 다음 경계를 대조한다.

- 공통 기반과 분야 DSGA의 규칙 제정 범위가 겹치지 않음
- payload 미결정 상태를 구현 완료로 표기하지 않음
- Provider·Consumer 기능을 고정 기관 역할로 바꾸지 않음
- 요금 원장과 notary 증적을 하나의 중앙 거래 원장으로 합치지 않음
- payload가 운수사 원천에서 기존 정산 시스템으로 직접 이동함
- E-20의 세 조건과 미확인 판정 기준을 확정값으로 바꾸지 않음
