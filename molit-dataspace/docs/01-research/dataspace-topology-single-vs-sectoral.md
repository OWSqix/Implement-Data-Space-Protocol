# 국토교통 데이터 스페이스 구성 연구: 단일형과 분야형

작성일: 2026-07-30  
작성 기준: 2026-07-30  
상태: Draft  
작성자: 연구 담당  
관련 결정: [ADR-0003](../adr/0003-existing-platform-integration-topology.md) — 이 문서의 권고 확정은 별도 ADR 필요

## 1. 목적과 범위

- **(목적)** 7대 분야 전체를 하나의 데이터 스페이스로 운영하는 단일형과, 공통 기반 위에 분야별 데이터 스페이스를 두는 분야형 중 구성 방향의 판단 근거 제공
- **(질문)** 어느 계층을 국토교통 공통으로 통합하고, 어느 계층을 분야별로 분리하는가
- **(포함 범위)** 국제 준거 비교, 판정 기준 4개 축, 7대 분야 적용, 권고안
- **(제외 범위)** 구성의 최종 결정 — ADR로 확정, 기존 플랫폼 연계 방식 — [ADR-0003](../adr/0003-existing-platform-integration-topology.md)의 범위, Connector 제품 선택
- **(판정 기준)** 시맨틱 통합 가능성, 분야 간 유지 동력 격차, 크로스도메인 유즈케이스 요구, 중복 구축 비용

이 문서의 단일형은 7대 분야가 하나의 회원·거버넌스·정책 체계를 공유하는 구성이고, 분야형은 신뢰·발견 등 공통 기반을 공유하되 분야별로 거버넌스와 페이로드 표준을 분리하는 구성이다. 데이터 스페이스의 단위 문제와 기존 플랫폼의 연계 방식 문제를 구분하며, 후자는 이 문서에서 다루지 않는다.

## 2. 현재 판정

### 2.1 핵심 판정

- **(판정)** 단일형 대 분야형의 이분법이 아니라 계층 분리 문제로 판정함
  - **(권고)** 신원·신뢰, 커넥터·프로토콜 프로파일, 카탈로그 연합, 공간 참조 체계는 국토교통 공통으로 통합
  - **(권고)** 페이로드 표준, 유즈케이스 거버넌스, 회원·요금 체계는 분야별 데이터 스페이스로 분리
- **(판정)** 완전 단일형은 광역 단일 데이터 스페이스의 관찰 경로를 반복할 위험 — 페이로드 표준화가 최소공배수인 메타데이터 계층으로 후퇴함. 근거: 3.1절
- **(판정)** 공통 기반 없는 분야별 신설은 신원·인증·커넥터의 중복 구축과 크로스도메인 유즈케이스 차단을 낳음. 근거: 4.4절
- **(조건)** 분야형을 채택해도 데이터 스페이스 신설은 유지 동력이 확인된 분야로 한정 — [참여 유인 분석](sector-adoption-levers.md) 5절의 우선순위와 결합
- **(거버넌스 판정)** 국가 프레임 아래 국토교통 공통 기반을 두고 공통 기반·분야 DSGA 2계층과 과제 관리·규칙 제정·운영 3분리를 등록 — [ADR-0007](../adr/0007-governance-function-separation.md) `Proposed`

## 3. 국제 준거

세 구성 유형의 관찰을 비교 준거로 사용한다. 상세 근거는 [활성화 실태 조사](dataspace-landscape-survey.md)에 있다.

### 3.1 단일 광역형 — MDS

- **(관찰)** 독일 MDS는 모빌리티 전반을 하나의 데이터 스페이스로 묶고, 페이로드 시맨틱은 기존 도메인 표준에 위임함 — [MDS·Mobilithek 참조 사례](mds-mobilithek-reference-case.md)
- **(관찰)** 참여자 수와 상업 실적 수치는 미공개 상태 — [활성화 실태 조사](dataspace-landscape-survey.md) 4.1절
- **(해석)** 범위가 넓을수록 합의 가능한 표준화 깊이가 얕아지고, 데이터 스페이스의 차별성이 발견 계층으로 한정됨. 상태: `Inferred`

### 3.2 협역 수직형 — Catena-X

- **(관찰)** 자동차 밸류체인 하나에 집중하고, 부품·차량 식별자와 디지털 트윈 백본 위에 유즈케이스별 aspect model을 누적하는 구조 — [활성화 실태 조사](dataspace-landscape-survey.md) 3절
- **(해석)** 시맨틱 깊이의 성립 조건은 좁은 범위 자체가 아니라 분야 공통의 공유 엔티티임. 상태: `Inferred`
- **(관찰)** 깊이를 확보하고도 확산에는 규제와 구매력 전가가 필요했음 — 같은 문서 5.1절. 구성 선택이 확산 문제를 대신 풀지 않음

### 3.3 프레임형 — Manufacturing-X와 유럽연합 공통 기반

- **(관찰)** 독일 Manufacturing-X는 재정 프로그램 아래 Factory-X, Chem-X, Aerospace-X, Semiconductor-X, Construct-X 등 분야 프로젝트를 두고, Catena-X 청사진과 Tractus-X 구성요소를 재사용하는 구조 — [활성화 실태 조사](dataspace-landscape-survey.md) 4.3절
- **(관찰)** 유럽연합도 같은 구조 — 섹터별 데이터 스페이스에 공통 미들웨어(Simpl)와 공통 청사진(DSSC)을 결합
- **(관찰)** 분리된 데이터 스페이스 간 데이터 교환은 Ouranos와 Catena-X의 상호운용 PoC로 성립 선례가 있음(2025-03-31) — 같은 문서 4.1절
- **(제한)** Manufacturing-X 분야 프로젝트는 전부 개발·파일럿 단계로, 프레임형의 운영 실증 사례는 아직 없음 — 같은 문서 4.3절, 확인일 2026-07-30. 프레임형 채택을 성공 근거로 인용할 수 없음

## 4. 판정 기준과 7대 분야 적용

### 4.1 시맨틱 통합 가능성 — 공유 엔티티

- **(전제)** Catena-X형 시맨틱 통합의 성립 조건은 분야 공통의 공유 엔티티 — 3.2절
- **(관찰)** 국토교통 7대 분야의 횡단 앵커는 공간 참조임 — 건물·필지·도로 구간·노선 등 7대 분야의 대상이 모두 공간 객체에 앵커링됨
- **(관찰)** 공간 참조 항목은 이미 [메타데이터·정책 프로파일](../02-architecture/metadata-and-policy-profile.md)이 CRS·좌표 축 순서·도로망 node/link version으로 관리 중
- **(판정)** 공간 참조는 발견·연결 계층의 앵커이고, 분야 페이로드 — 공사 내역, 운행 기록, 안전점검 결과 — 의 시맨틱을 통합하지 못함
  - **(귀결)** 공간 참조 체계는 공통 계층에 배치하고, 페이로드 표준은 분야별로 분리
  - **(대비)** Catena-X의 부품 식별자는 페이로드까지 관통하는 앵커이나, 공간 참조는 위치 결합까지만 관통함. 상태: `Inferred`

### 4.2 분야 간 유지 동력 격차

- **(관찰)** 유지 동력 3개가 걸리는 분야는 건설과 교통모빌리티뿐이고, 도로·철도·항공은 동력이 1개 수준 — [참여 유인 분석](sector-adoption-levers.md) 5절
- **(판정)** 단일형은 회원 규약·정책 개정·표준 승인 속도가 가장 느린 분야에 전체가 결합되는 구조적 비용을 가짐. 상태: `Inferred`
- **(판정)** 분야형은 준비된 분야부터 착수하고 분야별 규약 개정을 독립시킬 수 있음 — 동력 격차가 클수록 분야형의 상대 이점이 커짐

### 4.3 크로스도메인 유즈케이스 요구

- **(관찰)** 기획보고서는 분야별 개별 플랫폼 연결과 이종 분야 융합형 AI 서비스 생성을 목표로 명시함. 근거: `SRC-REPORT-001` 보고서 p.14
- **(판정)** 융합 요구는 단일 거버넌스의 근거가 아니라 공통 발견 계층과 공통 정책 어휘의 근거임 — 검색·계약·정책 표현이 호환되면 거버넌스가 분리되어도 교차 사용 가능
  - **(근거)** 조직·표준이 분리된 Ouranos와 Catena-X가 중간 계층으로 데이터 교환을 성립시킨 선례 — 3.3절
- **(조건)** 분야 데이터 스페이스 간 상호운용 시험을 공통 기반의 검증 항목으로 두어야 성립 — 5.3절

### 4.4 중복 구축 비용

- **(판정)** 분야별 신설 시 신원·인증, 커넥터 배포, 카탈로그, 운영 감시가 분야 수만큼 중복될 위험 — 공통 기반으로 통합할 계층의 실체
- **(관찰)** 저장소의 CaaS·DSaaS 컨트롤 플레인은 dataspace 식별자와 tenant를 분리해 복수 데이터 스페이스 운영을 전제함 — [EDC CaaS·DSaaS 아키텍처](../02-architecture/edc-caas-dsaas-architecture.md)
- **(판정)** 분야형 채택 시 공통 기반 계층은 신규 설계가 아니라 기존 구현 자산의 배치 문제로 축소됨

## 5. 권고안

### 5.1 국가 프레임 아래의 2계층 구성

- **(상위 경계)** 국토교통 2계층 구성은 국가 프레임 아래에 배치 — 국가 프레임 원문과 위임 범위는 `Unverified`
- **(권고)** 국토교통 공통 기반 한 벌 — 참가자 신원·신뢰, 커넥터·프로토콜 프로파일, MOLIT DCAT-AP 기반 카탈로그 연합, 공간 참조 체계, 공통 정책 어휘
- **(권고)** 그 위에 분야 데이터 스페이스 — 분야 회원·거버넌스, 페이로드 표준, 유즈케이스 로드맵, 요금·정산
- **(경계)** 공통 기반은 분야 데이터 스페이스의 페이로드 표준을 승인하지 않음 — 표준 관리 주체와 서비스 판매 주체의 분리 원칙을 계층 간에도 적용. 근거: [활성화 실태 조사](dataspace-landscape-survey.md) 5.5절

### 5.2 착수 순서

- **(권고)** 분야 데이터 스페이스는 유지 동력 3개가 확인된 건설과 교통모빌리티부터 착수
- **(권고)** 도로는 신설 없이 공공 보유 데이터의 Provider로 공통 기반에 참여 — 환류 시범의 형태
- **(권고)** 철도·항공은 신설 보류 — 기관 간 직접 연계 대비 편익이 커넥터 운영 비용을 상회한다는 판정이 나올 때까지. 판정 기준: [참여 유인 분석](sector-adoption-levers.md) 4.7절
- **(완료조건)** 각 분야 착수의 인정 기준은 정기 교환 문서·데이터의 종류와 건수 목표를 착수 문서에 수치로 정의하는 것 — 회원 수 목표는 인정 기준으로 사용하지 않음

### 5.3 크로스도메인 처리

- **(권고)** 융합 유즈케이스는 분야 데이터 스페이스 간 상호운용 시험으로 구현 — 공통 카탈로그 검색, 정책 어휘 호환, 계약·전송의 교차 실행을 공통 기반의 검증 항목으로 등록
- **(권고)** 첫 교차 시험 후보는 교통모빌리티와 도시건축의 결합 — 기획보고서의 융합 목표와 공간 참조 앵커가 겹치는 지점

### 5.4 결정 절차

- **(제한)** 이 문서는 연구 권고이며 구성 확정이 아님 — 구성 결정은 결정권자·재검토 조건을 포함한 별도 ADR로 기록
- **(제한)** 배치 방식 — 플랫폼 자체 Connector, Bridge, CaaS — 은 이 권고와 독립적으로 [ADR-0003](../adr/0003-existing-platform-integration-topology.md)의 선택지 표를 따름

## 6. 거버넌스 기능과 권한 계층

[ADR-0007](../adr/0007-governance-function-separation.md)은 다음 3분리와 2계층 DSGA를 `Proposed`로 등록한다. 승인 전에는 현행 기관 배치로 간주하지 않는다.

| 기능·계층 | 제안 책임 | 제안 비책임 | 상태 |
| --- | --- | --- | --- |
| 과제 관리 | 연구개발 일정·산출물·성과 승인 기록 | 데이터 스페이스 규칙 제정과 운영 계약 집행 | 후보 — ADR-0007 Proposed |
| 공통 기반 DSGA | 국가 상위 제약 안의 참가·프로토콜 프로파일·공간 참조 규칙 제정 | 분야 규칙의 세부 제정과 서비스 운영 | 후보 — ADR-0007 Proposed |
| 분야 DSGA | 공통 기반 제약 안의 분야 회원·페이로드 표준·유즈케이스 규칙 제정 | 공통 프로파일 개정과 서비스 운영 | 후보 — ADR-0007 Proposed |
| 운영 주체 | 승인된 규칙에 따른 공통 서비스·운영 절차 실행 | 규칙 제정과 과제 성과 승인 | 후보 — ADR-0007 Proposed |

- **(분리 근거)** [활성화 실태 조사](dataspace-landscape-survey.md) §5.5의 표준 관리 주체와 서비스 판매 주체 분리 원칙을 과제 관리·DSGA·운영 기능으로 확장 제안
- **(축 구분)** 이 절의 2계층 DSGA는 5.1절의 2계층 토폴로지(공통 기반·분야)와 같은 분할을 권한 축에 적용한 것이며, 국가 프레임은 그 위의 상위 제약임
- **(Unverified)** 과기부의 국가 프레임 지정, KAIA 전담기관 위임 예정과 도메인별 거버넌스 구상은 전언 기반이며 원문을 확보하지 못함
- **(Unverified)** KAIA 위임 성격이 과제 관리인지 DSGA인지 확인되지 않음

국가 프레임 원문, KAIA 위임 문서와 정관 권한 조항을 확보한 뒤 역할별 주체를 확정한다. 확인 항목은 8절의 `OPEN-TOP-06`, `OPEN-TOP-07`에서 관리한다.
