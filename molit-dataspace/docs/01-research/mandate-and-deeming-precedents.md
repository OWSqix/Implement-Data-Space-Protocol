## 1. 목적과 범위

- **(목적)** 기존 정산 제출경로를 국토교통 데이터 스페이스 경유로 대체하거나 연결할 때 필요한 법적 장치와 일정의 판정 근거 제공
- **(질문)** 시스템 경유가 기존 제출의무를 소거한 선례는 무엇이며, 6개 도시의 준공영제 정산경로를 바꾸려면 어느 문서를 개정해야 하는가
- **(포함 범위)** 해외 의무화·수리·게이트웨이 6유형, 국내 직접 간주 10개 조문·7개 제도, 서울·인천·대전·부산·대구·광주 조례
- **(포함 범위)** 조례·규칙·운영·정산지침·협약의 권한, 권고 간주문안, 공포 뒤 준비기간과 착수 조건
- **(제외 범위)** 데이터 스페이스 기술 아키텍처, 정산 스키마 상세, 법률의견 확정, 자치법규안의 최종 입안
- **(판정 기준)** 의무행위 자체의 경유 지정, 기존 의무 이행 간주, 행정청의 수리, 기존 시스템 경유 전송, 결과규제, 자발적 유도로 구분
- **(판정 기준)** 완전 대체와 기존 의무 시스템에 정상 접수시키는 게이트웨이형을 분리하고, 필요한 최고 개정 층위를 판정

| 상태 | 적용 기준 |
| --- | --- |
| `Verified` | 1차 원문에서 직접 확인한 사실 |
| `Inferred` | 확인 사실에서 도출한 적용 판정 |
| `Unverified` | 필요한 문서를 확보하지 못한 상태 |
| `Decision` | 이 문서가 제안하는 선택 |

선례 수는 전수통계가 아니라 국가법령정보센터 현행 원문을 직접 확인한 보수적 하한이다. 외부 자료의 확인일은 모두 2026-08-02다. 발행일을 확인하지 못한 자료는 추정하지 않는다.

ENTSO-E, CTIS, RED III, BDI와 NEDO는 입력 원문에 영문 완전명이 없어 원문 식별자를 유지했다.

### 1.1 읽기 주의 — 조사 원문 용어와 저장소 아키텍처의 관계

- **(Verified — 문서 성격)** 이 문서는 **조사 원문을 전사한 기록**이며 설계 결정문이 아니다.
- **(Verified — 용어 출처)** 본문의 **"게이트웨이"는 조사자의 용어**다.
- **(Decision — 적용 기준)** 저장소의 아키텍처 취급은 [ADR-0002](../adr/0002-data-stays-at-source.md)와 [ADR-0008](../adr/0008-provider-default-and-existing-system-participation.md)을 따른다.
  - **(경계)** **데이터 스페이스는 payload를 보관하지도 중계하지도 않는다.** 참가자는 제공 가능한 상태를 만들고 수요자는 계약을 맺고 원천에서 당겨간다.
- **(Decision — OPEN-MAN-12 처리)** `OPEN-MAN-12`의 게이트웨이 방향 선택지 자체가 **폐기됐다.** 데이터 스페이스가 payload를 보관·중계하는 구도를 전제했기 때문이다.
  - **(Decision — E-19)** 기존 정산 시스템(회계처리·버스경영관리시스템)은 **Consumer로 온보딩**한다. 계약을 맺고 운수사 원천에서 당겨온다
- **(해석 경계)** 본문에 중앙 수신·중계로 읽히는 서술이 있다면 그것은 조사 원문의 표현이며 채택된 설계가 아니다.
- **(Decision — OPEN-MAN-13 처리)** `OPEN-MAN-13`의 제출 시점 선택안은 **`E-20`으로 결정됐다.** 본문의 선택지 나열은 결정 이전 기록이다.
  - **(Decision — E-20)** 제출 이행은 **계약 체결 + 수신 가능 상태 + 기술적 온보딩 완료**의 세 조건이 모두 충족된 때 성립한다
- **(해석 경계)** 본문의 **중앙 수신·중계 전제와 권고 간주문안**은 조사 원문의 표현이며, 저장소가 채택한 문안은 [교통모빌리티 분야 규약 골격 §9.3](../02-design/sector-rulebook-framework.md#93-간주-문안-제안)에 있다.
- **(Decision — E-15)** 기존 **제출 창구** 대체 목표를 **2028년**으로 옮기고 2027년은 병행 시범·준비기간으로 재정의한다 — 근거: `E-15`, 기준일 2026-08-03
  - **(기록 범위)** 본문의 **2027년 관련 일정 서술은 조사 시점 원문**이다. 근거: 이 문서의 작성 기준, 확인일 2026-08-03

## 2. 현재 판정

### 2.1 핵심 판정

- **(Verified)** 해외에서는 의무경로 지정부터 자발적 인증까지 6유형이 확인됨
  - **(근거)** 3절의 유형별 1차 원문 — `SRC-MAN-001`~`SRC-MAN-021`
- **(Verified)** 유럽연합 국가접근점(National Access Point, NAP)은 간주가 아니라 NAP 경유 자체가 의무의 내용임
  - **(근거)** Delegated Regulation (EU) 2017/1926 제4조제3항과 독일 지능형교통시스템법(Intelligente-Verkehrssysteme-Gesetz, IVSG) 제5조제1항 — `SRC-MAN-001`, `SRC-MAN-003`
- **(Verified)** 국내 직접 간주는 최소 10개 조문·7개 제도에서 확인됨
  - **(근거)** 폐기물, 부동산거래, 시설물, 나라장터, 자동차, 지하안전, 냉매 법령·고시 — `SRC-MAN-022`~`SRC-MAN-028`
- **(Verified)** 폐기물관리법 제45조제3항은 조사 범위에서 유일한 법률상 간주임
  - **(조건)** 나머지 간주는 시행규칙 또는 조달청 고시에 있음 — 4.1절
- **(Inferred)** 시설물안전법 시행규칙 제3조제6항은 목표 구조의 정확한 국내 원형임
  - **(근거)** 관리주체의 1회 제출로 시·군·구→시·도→국토교통부의 연쇄 보고·제출을 소거 — `SRC-MAN-024`
- **(Inferred)** 협약만으로는 법정 제출 간주가 생기지 않음
  - **(근거)** 협약은 당사자의 운영 책임을 정할 수 있지만 상위 자치법규의 의무와 특정 시스템 명령을 변경하지 못함 — 5절, 6절
- **(Decision)** 조례에는 간주효과 또는 명시적 위임을 두고, 제품명 대신 기능적 정보처리체계를 규정하는 방안을 제안
  - **(조건)** 도시별 기본형·게이트웨이형과 전송 방향은 결정 전 — `OPEN-MAN-12`, `OPEN-MAN-13`

### 2.2 일정 판정

- **(Verified)** 부산과 광주는 공포 뒤 각각 약 9개월과 약 6개월의 시스템 준비 선례를 남김 — `SRC-MAN-049`, `SRC-MAN-044`, `SRC-MAN-050`
- **(Verified)** 폐기물관리법 제45조제3항은 2007-08-03 개정 뒤 2008-08-04 시행되어 약 12개월의 준비기간을 둠 — `SRC-MAN-022`
- **(Verified)** 인천 이행협약은 2025-09-01 체결됐고 2년 주기 합의 개정과 이견이 없을 때 자동 갱신을 규정함 — `SRC-MAN-034`
- **(Inferred)** 2027년 9월 전 인천 협약 변경에는 별도 중도합의가 필요함 — `SRC-MAN-034`, 확인일 2026-08-02
- **(Inferred)** 2027년 1월 이후 병행 시범착수는 가능하지만 기존 제출경로를 전면 폐지하는 일정은 성립하기 어려움 — `SRC-MAN-022`, `SRC-MAN-034`, `SRC-MAN-049`, `SRC-MAN-050`

### 3.2 NAP와 Mobilithek

- **(Verified)** Delegated Regulation (EU) 2017/1926 제4조제3항은 데이터 보유자가 NAP를 통해 자료를 제공하도록 규정함 — `SRC-MAN-001`

> “The data holders shall provide … data through the national access point …”

- **(Inferred)** 이 조문은 “다른 곳에 제출해도 NAP에 제출한 것으로 본다”는 간주가 아님
- **(Inferred)** NAP 경유 제공 자체를 의무행위로 정의하므로 실질적으로 간주보다 강한 구조에 해당
- **(Verified)** Delegated Regulation (EU) 2022/670 제3조제6항은 제3자 데이터 제공자와 집계기관 경유를 허용함 — `SRC-MAN-002`
  - **(책임)** 경유를 사용해도 최종 책임은 원자료 보유자에게 남음
- **(Verified)** 독일 IVSG 제5조제1항도 NAP를 통한 제공을 의무행위로 규정함 — `SRC-MAN-003`

> “Die zuständigen Stellen haben Daten … über den Nationalen Zugangspunkt bereitzustellen.”

- **(Verified)** 독일 정부 문서가 지칭하는 NAP는 Mobilithek임 — `SRC-MAN-005`, `SRC-MAN-052`
- **(Verified)** IVSG 제6조제2항과 PBefG 제3a조는 중간기관 또는 주정부 집계시스템 제출 뒤 NAP로 즉시 전달하는 구조를 허용함 — `SRC-MAN-003`, `SRC-MAN-004`
- **(Unverified)** MDS 제출을 NAP 의무 이행으로 인정하는 조문은 확인되지 않았음 — `OPEN-MAN-01`
  - **(경계)** Mobilithek는 법정 NAP이고 MDS는 자발적 데이터 생태계임 — `SRC-MAN-005`, `SRC-MAN-006`

### 3.3 기존 의무 이행과 복수 플랫폼 수리

- **(Verified)** Regulation (EU) 543/2013 제4조제2항은 원자료 보유자가 중앙 플랫폼에 직접 제출해 기존 의무를 이행할 수 있다고 명시함 — `SRC-MAN-007`

> “Primary owners of data may fulfil their obligation … by submitting data directly…”

- **(Inferred)** ENTSO-E Transparency Platform은 조사 범위에서 가장 정확한 해외 간주 원형임
  - **(조건)** 제3자 제공자를 이용해도 원자료 보유자의 책임은 유지됨
- **(Verified)** eFTI Regulation 제4조제2항은 전자방식을 택할 때 인증된 eFTI 플랫폼 사용을 규정함 — `SRC-MAN-008`
- **(Verified)** 같은 규정 제5조는 행정청이 인증 플랫폼을 통한 자료를 수리하도록 규정함 — `SRC-MAN-008`
- **(Inferred)** eFTI는 특정 사업자를 독점 지정하지 않고 인증된 복수 플랫폼의 법적 수리효과를 인정한 유형에 해당
- **(Verified)** Clinical Trials Regulation 제5조제1항은 신청서를 제80조의 유럽연합 포털로 제출하도록 규정함 — `SRC-MAN-009`
  - **(병행)** CTIS는 2022-01-31 개통 뒤 신규 신청 1년, 기존 임상시험 3년의 이전기간을 둠 — `SRC-MAN-010`

### 3.4 재생에너지지침 게이트웨이형

- **(Verified)** Directive (EU) 2023/2413(RED III) 제31a조제5항은 국가 데이터베이스 자료가 Union Database로 “instantly transferred”될 때 국가 데이터베이스 이용을 허용함 — `SRC-MAN-011`
- **(Verified)** 국가 데이터베이스와 제3자 시스템은 존속하고 최종 품질승인은 Union Database에서 수행됨 — `SRC-MAN-012`
- **(Inferred)** 기존 의무 시스템을 유지하면서 중앙 인프라로 즉시 전송하는 국토교통 게이트웨이형의 직접 준거에 해당

### 3.5 Catena-X 결과규제형

- **(Verified)** EU Battery Regulation 제77조는 2027-02-18부터 배터리 여권을 요구하지만 Catena-X 또는 Cofinity-X를 지정하지 않음 — `SRC-MAN-013`
- **(Verified)** Regulation (EU) 2024/1781도 디지털 제품여권과 상호운용성을 규정하지만 특정 데이터 스페이스를 지정하지 않음 — `SRC-MAN-014`
- **(Verified)** 폭스바겐 자료는 Catena-X 참여 강제가 없다고 설명함 — `SRC-MAN-015`
- **(Verified)** BMW는 2025년 4월부터 Catena-X 등록을 조달 프로세스의 일부로 반영한다고 발표함 — `SRC-MAN-016`
- **(Verified)** Catena-X Data Space Accelerator는 중소기업 온보딩 보조를 포함함 — `SRC-MAN-056`
- **(Inferred)** Catena-X는 법률상 지정이 아니라 결과규제, 정부보조와 구매계약을 결합한 유형에 해당
- **(Unverified)** BMW 등 완성차 제조사의 실제 표준구매계약 조문은 공개 원문을 확인하지 못했음 — `OPEN-MAN-02`

### 3.6 Ouranos와 BDI·iSHARE 자발형
