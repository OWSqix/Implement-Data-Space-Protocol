# ADR-0006: 선별적 notary 증적 체제

작성일: 2026-07-30  
상태: Proposed  
결정 범위: 거래 증적 체제와 적용 판정  
결정권자: 프로젝트 의뢰자

## 1. 목적과 결정 요약

이 ADR은 제3자 정산·보조금·감사 요구가 있는 거래와 그 밖의 거래에 적용할 증적 체제를 제안한다.

- **(결정)** 법적·계약적 근거가 확인된 제3자 정산·보조금·감사 요구 거래는 중앙 notary 기록 대상으로 지정
- **(결정)** 그 밖의 거래는 참여자 로컬 감사 로그와 공통 감사 ID로 연결
- **(판정 보류)** 적용 근거가 확인되지 않은 거래는 중앙 기록 대상으로 승격하지 않고 로컬 감사 로그와 공통 감사 ID를 남기는 fail-closed 적용
- **(D-01)** notary record는 서명 hash·시각·공통 감사 ID만 담는 존재 증명으로 한정하고 당사자·자산 식별정보를 포함하지 않음
- **(D-02)** 정기 정산 범위는 회원약정의 사전 동의에 따라 자동 제출하고, 범위 밖·감사·분쟁 개봉은 건별 법적 근거를 확인하며 개봉 이력도 감사 ID로 기록
- **(미결정)** notary 서비스의 배치 위치와 운영 주체는 이 ADR의 결정 범위에서 제외

이 결정은 증적 체제와 배치 결정을 분리한다. 배치는 6절의 record 요건과 운영 주체가 확정된 뒤 별도 ADR에서 결정한다.

부분 충족 상태는 다음과 같다. record 요건 4개 중 스키마는 충족했고 열람 절차는 정의했으나 주체별 권한은 미정이다. 민감도와 보존은 미확정이며 배치 후보도 선택하지 않았다.

## 2. 배경과 제약

프로젝트 의뢰자는 전수 중앙 기록안을 검토한 뒤 거래 관계망 노출과 참여 유인 저하 가능성을 결정 사유로 기록했다. 정부·지자체가 거래 당사자가 아니면서 정산·감사 증거를 요구하는 거래만 중앙 기록 대상으로 좁혔다.

- **(확장 제안)** [ADR-0003](0003-existing-platform-integration-topology.md) §6 항목 7의 Provider 내부 감사 ID 연결을 참여자 간 기록 대사 범위로 확장
- **(기존 결정 유지)** ADR-0003의 상태는 `Accepted`로 유지
- **(후속 영향)** 이 ADR이 승인되면 `FR-AUD-001`과 `OP-AUD-001`의 참여자 간 범위 개정 필요
- **(Unverified)** 거래 유형별 중앙 증적 의무의 법적·계약적 근거는 확인 전이다. 거버넌스·법무 담당이 지자체 조례·협약, 발주 계약과 감사 규정 조문을 대조하고 결과를 [R-053](../03-plan/risk-register.md)에 기록한다.

IDSA Rulebook Release 2026-1은 audit·notary 기능을 Observability Services 범주로 분류하고 정책 집행·검증의 일차 책임을 참여자에게 둔다. 근거: [IDSA Rulebook 역할](https://kb.internationaldataspaces.org/external/rulebook/005_Roles/), [IDSA Rulebook 정책](https://kb.internationaldataspaces.org/external/rulebook/105_Policies/), 확인일 2026-07-30

## 3. 선택지

| 선택지 | 판정 | 사유 |
| --- | --- | --- |
| 전 거래 중앙 기록 | 기각 | 거래 관계망 노출 범위가 의무 대상보다 커지고 참여자 로컬 책임과의 경계가 불명확함 |
| 근거가 확인된 거래만 중앙 기록 | 채택 제안 | 제3자 증적 요구와 그 밖의 거래를 판정 근거로 분리 가능 |
| 전 거래 참여자 로컬 기록 | 기각 | 제3자 정산·보조금·감사 요구 거래의 중앙 대사 지점을 제공하지 못함 |

## 4. 결과

- **(적용 결과)** 증적 경로를 중앙 기록 대상과 참여자 로컬 기록 대상으로 구분
- **(운영 제약)** 거래별 법적·계약적 근거와 판정 증거를 연결하지 못하면 중앙 기록 대상으로 지정할 수 없음
- **(설계 제약)** notary record의 민감도·주체별 열람 권한·보존 범위 확정 전에는 배치 후보를 결정할 수 없음
- **(기존 요구 영향)** ADR-0003 §6 항목 7의 단일 Provider 내부 연결은 유지하며 참여자 간 대사는 승인 후 확장

### 4.1 존재 증명 record

notary record는 다음 세 값만 기록한다.

| 필드 | 의미 | 금지 입력 |
| --- | --- | --- |
| 서명 hash | 당사자가 보관한 원문 증거의 무결성 결합 | 원문 payload·서명문·당사자명 |
| 시각 | record 접수 또는 고정 시각 | 업무 사건의 추정 시각 |
| 공통 감사 ID | 당사자가 제시하는 로컬 기록 조인 키 | 자산명·계약 내용·기관 식별정보 |

정산자는 당사자가 제시한 공통 감사 ID로 record 존재를 조회한다. record만으로 당사자, 자산, 금액이나 법적 책임을 판정하지 않는다.

### 4.2 하이브리드 개봉 절차

| 구분 | 선행 조건 | 동작 | 실패 처리 |
| --- | --- | --- | --- |
| 정기 정산 범위 | 회원약정에 제출 범위·주기·목적의 사전 동의가 있음 | 당사자 로컬 증거와 감사 ID를 정산 절차에 자동 제출 | 범위·동의·계약 상태가 불명확하면 제출 차단 |
| 범위 밖·감사·분쟁 | 건별 법적·계약적 근거와 승인 기록이 있음 | 승인 범위의 증거를 개봉하고 개봉 사건을 새 감사 ID로 기록 | 근거·승인·범위 중 하나라도 없으면 fail-closed |

이 절은 열람 절차만 정의한다. 거래 당사자·제3자·운영자의 주체별 열람 권한은 6절 재검토 조건으로 남는다.

## 5. 검증

`OP-AUD-001` 확장안은 다음 대사 시험으로 구성한다. 이 ADR이 `Accepted`로 전환되기 전에는 현행 시험의 규범 범위를 바꾸지 않는다.

1. 법적·계약적 근거가 확인된 제3자 정산 거래에서 중앙 notary 기록, 양측 로컬 로그와 공통 감사 ID를 조회한다.
2. 중앙 record는 공통 감사 ID·서명 hash·존재·시각만 대조한다. 거래 식별자와 업무 상태는 양측 로컬 로그에서만 대사하고 불일치 건수를 결과에 기록한다.
3. 중앙 기록 비대상 거래에서 중앙 notary 기록이 생성되지 않고 양측 로컬 로그가 공통 감사 ID로 연결되는지 확인한다.
4. 판정 근거가 없는 거래에서 중앙 기록 승격이 차단되고 로컬 로그와 공통 감사 ID가 남는지 확인한다.
5. 정기 정산 범위의 사전 동의가 유효할 때만 자동 제출되고, 범위 밖·감사·분쟁 개봉은 건별 근거가 없으면 차단되는지 확인한다.
6. 개봉 사건에 원 record와 다른 감사 ID가 생기고 승인 범위·시각·결과가 연결되는지 확인한다.
7. 시험 결과에는 적용 근거 문서 ID, record schema version, 참여자별 감사 export와 대사 보고서를 연결한다.

통과 조건은 대상 거래의 세 기록 연결 성공, 비대상·판정 보류 거래의 중앙 기록 0건, 로컬 감사 ID 연결과 무근거 개봉 0건이다.

## 6. 재검토 조건

- 법적 근거: [`R-053`](../03-plan/risk-register.md)의 법적·계약적 적용 근거 확인. 현재 `Open`
- 민감도: record와 개봉 결과의 필드별 민감도 등급 확정
- 열람 권한: 거래 당사자·제3자·운영자의 주체별 권한 확정. D-02는 절차만 정의하며 [EDC 구성 설계 §5.1](../02-architecture/edc-caas-dsaas-architecture.md#51-notary-배치-선행-요건과-옵션-비교-축)의 선행 요건을 대체하지 않음
- 보존: 원 record·개봉 이력·대사 결과·backup의 보존·파기 범위 확정
- 운영 주체: notary 운영자, DSGA 감독과 책임 경계 확정

다섯 조건 중 하나가 갱신되면 이 ADR의 범위와 시험을 재검토한다. 배치 ADR은 다섯 조건을 모두 확인한 뒤 착수한다.
