# 파일럿 권리 확정 패키지

작성일: 2026-08-03  
작성 기준: 2026-08-03 저장소 정본과 2026-08-02 외부 자료 확인 결과  
상태: Draft  
적용 단계: 구축 계획 단계 0  
관련 결정: `E-12`, `E-13`, `E-15`, `E-16`, `E-17`, `E-18`, `E-19`, `E-20`, `E-21`, `T-04`
정정 기록: 2026-08-04 — 2026-08-03에 잘못 추가된 Consumer의 원천 직접 접근 서술을 `E-21`에 따라 Provider Data Plane 경유 PULL로 정정

## 1. 목적과 범위

- **(목적)** 파일럿 지자체 한 곳의 조례·협약·정산 위수탁계약과 운수사 데이터 권리를 문서 증거로 확정하기 위한 자료 확보 목록, 질문표, 판정 절차와 기록 서식 제공
- **(첫 행동)** 후보 도시의 현행 문서를 먼저 확보한다. 도시 선정 기준은 문서 완전성 Gate를 통과한 후보에만 적용한다.
- **(확정 질문)** 데이터셋별로 다음 세 가지를 판정한다.
  1. 계약별 Provider 기능을 누가 수행하는가
  2. 그 주체가 해당 데이터셋을 제3자에게 제공할 권한을 갖는가
  3. 어떤 항목이 제외·집계·폐쇄환경 대상인가
- **(포함 범위)** 서울·인천·대전·부산·대구·광주의 현행 법규와 운영문서, 정산 위수탁계약, 운수사 측 권리 문서, 초기 정산 데이터셋
- **(제외 범위)** 파일럿 도시의 사전 선택, 데이터셋 권리의 사전 허용, 법률의견 확정, 기술적 온보딩 완료 기준과 payload 필드의 임의 확정
- **(완료 기준)** 현행 원문, 데이터셋별 Provider 판정, 권리 9항목, 필드별 처리 방식, 근거 조문과 승인 기록이 서로 추적 가능해야 한다.
- **(증거 기준)** 구두 설명과 출처 없는 요약은 `Unverified — 문서 미확인`으로 유지한다. 현행 원문과 서명·승인 문서가 없으면 권리 판정은 `판정 불가`다.

- **(초기 교환 대상)** 정산명세·대사결과·공통 감사 ID
- **(초기 제외 대상)** 원시 교통카드, 개인·가명 식별값과 결제수단 원문
- **(미정 범위)** 상세 필드는 `DEF-05` 실물 조사와 분야 데이터 스페이스 거버넌스 기구(Data Space Governance Authority, DSGA) 승인 전까지 미정이다.
  - **(근거)** [초기 유즈케이스·KPI §3.1](initial-usecases-and-kpi.md#31-가치업무-경계), 확인일 2026-08-03

데이터 스페이스 공통 서비스는 신원·Catalog·계약·정책·감사를 담당하고 payload를 보관하거나 중계하지 않는다.
Consumer는 계약 범위에서 참가자(Provider)의 Provider Data Plane에 접근해 PULL하며, Data Plane이 source binding으로 원천에서 읽어 응답한다.
근거: [ADR-0002](../adr/0002-data-stays-at-source.md), [EDC 기반 CaaS·DSaaS 구성 설계 §6](../02-architecture/edc-caas-dsaas-architecture.md#6-offering-게시와-전송), 확인일 2026-08-03.

### 1.1 적용 결정

이 절에서 FPIS는 화물운송실적신고시스템을 뜻한다. 아래 결정문은 적용 과정에서 요약하거나 바꾸지 않는다.

- **(Decision — E-12)** 온보딩은 **복수 경로**로 하고 위임을 허용하되 **FPIS식 3분할 책임**을 적용한다. 참가자·원천시스템은 사실·증빙 책임, 대행자는 변환·전송·인증·로그 책임, 운영자는 접속·보안 책임을 진다
- **(Decision — E-13)** 제도화는 **고시·훈령을 먼저** 두고 **상위 법령은 뒤에 둔다**
- **(Decision — E-15)** 기존 **제출 창구** 대체 목표를 **2028년**으로 옮기고 2027년은 병행 시범·준비기간으로 재정의한다
  - **(근거)** `SRC-PRC-012`, 기준일 2026-08-03
- **(Decision — E-16)** 계약별로 **Provider 기능을 수행하는 주체의 기본값은 원천기관**이다. 허브가 특정 데이터셋에서 Provider 기능을 수행하려면 **포괄 위임이 문서로 확인**돼야 한다
- **(Decision — E-17)** 초기 출범을 **허브 섭외에 종속시키지 않는다.** `E-11`은 **유지하되 초기 범위에서 제외하고 확장 단계로 옮긴다**
- **(Decision — E-18)** 허브 연계 범위는 **재제공권 확인목록**으로 한다. 기본값은 미연계이고 재제공 권리가 문서로 확인된 데이터셋만 추가한다
- **(Decision — E-19)** 기존 정산 시스템(회계처리·버스경영관리시스템)은 **Consumer로 온보딩**한다. 계약을 맺고 운수사 원천에서 당겨온다
- **(Decision — E-20)** 제출 이행은 **계약 체결 + 수신 가능 상태 + 기술적 온보딩 완료**의 세 조건이 모두 충족된 때 성립한다
- **(Decision — E-21)** payload 전송은 **Provider Data Plane 경유로 단일화**한다. 원천 직접 방식(Consumer가 원천 token·signed URL로 원천에 직접 접근)은 채택하지 않는다

`E-19`의 “운수사 원천에서 당겨온다”는 업무 층위의 승인 문구다. Consumer에게 원천 접근권을 부여한다는 뜻이 아니며, 기술 전송은 Consumer가 Provider Data Plane에서 PULL하고 Data Plane이 source binding으로 운수사 원천에서 읽어 응답하는 경로를 따른다.

## 2. 현재 판정

### 2.1 문서 확보 Gate

- **(Decision — 잠정, 2026-08-06)** 파일럿 도시 우선 후보로 청주시를 기록한다. 협력 경로(충북대)를 근거로 하며 확정 전이다.
- **(Decision, 2026-08-06)** 본 패키지의 자료 확보 목록·질문지·선정축·권리 확인 항목은 청주시에 우선 적용한다. 청주시는 기존 6개 조사 도시 밖이므로 전 항목을 신규 판정한다.
- **(Unverified)** 청주시는 기초지자체로서 충청북도 조례·위임 관계 층위가 추가된다. 문서 층위 지도에 광역·기초 관계를 더해 재구성해야 하며 현행 문서는 전부 미확인이다.
- **(Unverified)** 6개 도시 전부 권리 확정에 필요한 현행 협약·정산지침 묶음이 문서 미확인이다. 인천은 2025-09-01 이행협약만 확인됐고 현행 회계·정산 세부기준은 문서 미확인이다.
- **(Verified)** [의무화·간주 규정 선례 조사 §5.3](../01-research/mandate-and-deeming-precedents.md#53-현행-문서-한계)는 6개 후보 중 현행 협약·정산지침 묶음이 완전하게 확인된 도시를 제시하지 못했다. 조사 외부 자료 확인일은 2026-08-02다.
- **(Verified)** 인천은 2025-09-01 이행협약 공개 원문이 확인됐다. 인천광역시는 2년 주기 합의 개정과 상호 의견이 없을 때 자동 갱신을 명시한다. 근거: `SRC-PRC-003`.
- **(Unverified)** 인천의 현행 회계·정산 세부기준과 데이터셋별 제3자 제공 권한은 문서 미확인이다.
- **(Unverified)** 서울·대전·부산·대구·광주의 현행 협약 또는 운영·정산지침 핵심 문서는 `OPEN-MAN-06`~`OPEN-MAN-10`과 연결된 문서 미확인 상태다.
- **(판정)** 현 상태에서는 6개 도시의 Provider 주체, 제3자 제공 권한과 필드별 처리 범위를 서로 같은 증거 수준으로 대조할 수 없다. 도시 선정은 **판정 불가**다.
- **(실행 조건)** 단계 0의 첫 산출물은 도시 점수표가 아니라 후보별 현행 문서 목록과 원문 묶음이다.

## 3. 자료 확보

### 3.1 확보 순서

1. 단계 0 자료 확보 담당자는 6개 도시 공통 문서 요구목록과 후보별 기확보 문서 목록을 작성한다.
2. 자료 확보 담당자는 자치법규정보시스템과 국가법령정보센터에서 조례·규칙의 현행 통합본문, 연혁, 별표와 서식을 확보한다.
3. 자료 확보 담당자는 지자체 교통부서와 정산주체에 현행 운영·정산지침, 협약, 정산 위수탁계약의 소관부서와 열람 경로를 먼저 묻는다.
4. 공개 원문이 없으면 자료 확보 담당자는 정보공개청구로 전문, 부분공개본 또는 비공개 근거와 문서 식별자를 요청한다.
5. 자료 확보 담당자는 운수사·조합에 참여 약정, 동의 구조, 제출 양식, 원천시스템과 보유 위치를 별도로 요청한다.
6. 법무·정산 검토자는 기관별 회신을 문서번호, 시행일, 유효기간, 서명 당사자와 별지 포함 여부로 대조한다.
7. 문서 완전성 Gate를 통과한 후보에만 5절의 질문표, 6절의 Provider 절차와 7절의 권리 체크리스트를 적용한다.
8. 도시 선정권자는 완성된 후보별 판정 서식을 비교해 별도 결정 기록을 남긴다. 선정권자와 시점은 미정이다.

문서가 일부만 확보된 후보는 확보된 사실을 폐기하지 않고 `Verified`로 기록한다. 다만 빠진 문서가 좌우하는 항목은 `Unverified — 문서 미확인`, 결론은 `판정 불가`로 유지한다.

### 3.4 문의 패키지

1차 문의는 문서 원문 자체보다 소관부서, 공식 접수 경로와 문서 식별자를 먼저 확인한다.


### 4.3 기술수준 자료의 사용 한계

- **(Unverified)** 전국 데이터 없음 — 판정 불가
- **(Verified)** 인천 준공영제 운수사 32개 중 17개, 53%가 2019년 외부 회계법인 기장으로 조사됐다. 전국 대표가 아니며 공통 ERP 설치 전후 상태도 문서만으로 분리되지 않는다. 근거: `SRC-PRC-009`.
- **(Verified)** 경기 시내버스 75개 중 65개, 86.7%가 2024년 ERP를 사용했으나 대부분 도 시스템과 미연계다. 자체기장률이나 자력 Offering 게시 가능률이 아니다. 근거: `SRC-PRC-010`.
- **(Verified)** 시내버스 388개사 중 50대 이하 업체는 105개사, 27.1%다. 자료의 기준연도·집계범위 안에서만 유효하며 전국 전산화 수준을 뜻하지 않는다. 근거: `SRC-PRC-011`.

지역·규모 수치는 `PRC-C-07`의 조사 질문을 정하는 근거로만 사용한다. 후보별 현행 자료가 없으면 기술수준 점수는 **판정 불가**다. 근거: [저기술 참가자 온보딩 선례 조사 §6](../01-research/low-tech-onboarding-precedents.md#6-국내-버스-실태), 확인일 2026-08-03.

## 5. 문서별 확인 질문

질문표의 초기 상태는 `Unverified — 문서 미확인`이다. 회신에는 문서번호, version 또는 개정일, 시행일, 유효기간, 정확한 조문·계약조항과 원문 위치를 붙인다. 질문 형식은 [운영기관 확인 질문](../01-research/operator-questionnaire.md)의 `ID · 질문 · 필요한 증거 · 상태` 형식을 따른다.

## 6. Provider 판정 절차

이 절은 §1.1의 `E-16`·`E-19` 결정문을 그대로 적용한다.

Provider는 기관의 고정 지위가 아니라 계약별 기능이다. 기관명이나 정산업무 수행 사실만으로 Provider 기능 주체를 확정하지 않는다. 아래 절차는 [원천·권리 인벤토리 §5](../01-research/source-and-rights-inventory.md#5-역할과-offering-provider-판정-절차)의 8단계를 준공영제 정산 입력에 맞춰 바꾼 것이다.

| 단계 | 입력 | 수행 동작 | 산출물 | 중단조건 |
| --- | --- | --- | --- | --- |
| 1. 범위 고정 | 현행 조례·규칙·운영·정산지침·협약·위수탁계약·운수사 문서 | 계약, 데이터셋, version과 전달 경로를 식별하고 `PRC-DOC-*`에 연결 | 데이터셋 판정 단위 | 현행 원문·별지 문서 미확인 |
| 2. 원천 판정 | 데이터 흐름도, 시스템대장, 데이터 사전, 정정 기록 | 최초 생성 주체, 현 보유 주체, system of record와 정정권자를 구분 | 원천·보유 책임표 | 원천과 사본·가공본 구분 불가 |
| 3. 역할 분리 | 업무분장, 계약 당사자, 위수탁 범위 | 운수사·지자체·조합·정산주체·수탁기관·대행자의 계약별 기능과 책임을 분리 | 역할·책임표 | 기관 지위만 있고 계약별 기능 근거 없음 |
| 4. 기본값 적용 | 2~3단계 결과와 `E-16` | 데이터셋의 원천기관을 Provider 기능 주체 기본값으로 기록하고 법적 계약 당사자를 대조 | 기본값 적용 기록 | 원천기관 식별 불가 |
| 5. 위임 판정 | 위임·대리·협약·위수탁·동의 문서 | 다른 주체가 기능을 수행하려면 범위·기간·재위임·권리 9항목·credential·사고책임의 포괄 위임을 확인 | 위임 문서·조항 대응표 | 포괄 위임 문서 미확인 |
| 6. Consumer·PULL 경로 | 계약 목적·수신자, Provider Data Plane 접근 정보, source binding, 접근자원 발급 절차 | 기존 정산 시스템을 Consumer로 배치하고 Consumer가 Provider Data Plane에서 PULL하며 Data Plane이 source binding으로 원천에서 읽어 응답하는 경로와 책임을 기록 | 계약별 Provider Data Plane 경유 PULL 경로 | Consumer 권한 또는 Provider Data Plane·원천 접근자원 발급 근거 미확인 |
| 7. 권리·보호 판정 | 7절 권리표, 개인정보·영업비밀·운행보안 문서 | 데이터셋·필드별 원본 전달, 집계, 폐쇄환경, 제외와 종료·철회 효과를 판정 | 데이터셋별 권리 판정서 | 권리 근거 또는 필드 분리 증거 미확인 |
| 8. 승인 기록 | 1~7단계 증거와 검토 결과 | 승인된 데이터셋만 Offering 게시 후보로 기록하고 미확인 항목을 9절에 등록 | 판정 ID, 승인·보류 기록 | 미확인 자산의 Offering 게시 금지 |

- **(전송 경계)** Provider transfer worker는 승인된 PULL 전송 사건을 받아 원천 플랫폼 token이나 signed URL을 발급하는 경계다.
  - **(source binding)** 발급 결과는 Connector를 거쳐 Provider Data Plane의 source binding이 된다.
  - **(노출 경계)** 발급 결과를 Consumer에게 노출하지 않는다.
- **(용어 경계)** 이 worker를 EDC Data Plane이나 DSP endpoint로 부르지 않는다.
- **(책임 경계)** 실제 바이트는 원천에서 Provider Data Plane을 경유해 Consumer로 이동한다. Provider Data Plane은 참가자(Provider)의 전송 경계이며 데이터 스페이스 공통 서비스는 payload를 보관·중계하지 않는다.

## 7. 데이터셋별 권리 분해 체크리스트

### 7.1 작성 단위와 판정값

체크리스트는 도시 전체나 협약 전체가 아니라 **데이터셋·version·전달 경로별로 한 부씩** 작성한다. 같은 데이터셋도 전달 경로와 계약 목적이 다르면 별도 판정한다.

| 식별 필드 | 기입값 |
| --- | --- |
| 권리 판정 ID | `PRC-RGT-미정` |
| 도시·정산주체 | 미정 |
| 데이터셋명·ID·version | 미정 |
| 원천시스템·최초 생성 주체 | 미정 |
| 현 보유 주체 | 미정 |
| 계약 목적·수신자·기간 | 미정 |
| 전달 경로 | Consumer가 Provider Data Plane에서 PULL하고 Data Plane이 source binding으로 원천에서 읽어 응답 |
| 적용 문서 ID | 미정 |

권리 결과는 `허용`, `조건부`, `금지`, `문서 미확인`, `판정 불가` 중 하나로 기록한다. 근거 상태는 별도 열에 `Verified`, `Inferred`, `Unverified`, `Decision` 중 하나로 기록한다. `해당 없음`은 적용 제외 근거 조항이 있을 때만 사용한다.

`Provider Data Plane 경유 PULL`은 `E-21`이 정한 전송 경로다.
Consumer는 계약 범위에서 Provider Data Plane에 접근하고 Data Plane이 source binding으로 원천에서 읽어 응답한다.
Provider Data Plane은 참가자(Provider)의 전송 경계이며 데이터 스페이스 공통 서비스가 아니다.
원본·집계·폐쇄환경·제외는 가능한 필드 처리 판정값일 뿐 이 문서가 특정 필드에 미리 채택한 방식이 아니다.

### 8.4 `E-20` 준비 상태

`OPEN-PRC-12`의 DS 경유 이행은 데이터 스페이스의 신원·Catalog·계약·정책·감사 절차를 뜻한다. payload는 Consumer가 Provider Data Plane에서 PULL하고, Data Plane이 source binding으로 원천에서 읽어 응답한다.
